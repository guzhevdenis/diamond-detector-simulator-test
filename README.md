# Diamond Detector Signal Simulator

Qt-приложение: генерация сигнала алмазного детектора, модель усилителя и амплитудный спектр.

## Сборка

Компилятор Visual Studio Community 2022 17.14.37614.0 (amd 64)

Отладчик CDB

Профиль Qt 6.4.1 (msvc2019_64)

CMake generator - Ninja 

```bash
cmake -S . -B build
cmake --build build
```

В Qt Creator: Open Project → `CMakeLists.txt`. Цель: `DiamondDetectorSIgnalGenerator`.

## Структура

```
src/app/          main.cpp, MainWindow
src/core/         расчёт (без виджетов)
src/ui/           графики и вкладка усилителя
third_party/      QCustomPlot — не править
data/             примеры шаблона и спектров
```

Зависимости только вниз: `app` → `ui` → `core`.

## Вкладки

1. **Signal Generator** — аналитическая модель импульса + амплитуды + времена событий → синтез → CSV/WLF.
2. **Amplifier Model** — CR-RC, усиление, шум, насыщение.
3. **Spectrum Analysis** — гистограммы пиков входа/выхода усилителя.

Экспорт CSV: `MainWindow::onExportCsv()` в `src/app/mainwindow.cpp`.

Во вкладке Signal Generator настройки расположены слева в прокручиваемой панели.
Нажатие на заголовок группы раскрывает или сворачивает её; по умолчанию открыта
только Pulse model. В группе Amplitudes отображаются поля выбранного распределения.
Кнопки Hide settings / Show settings скрывают и возвращают панель с сохранением
её ширины в текущем окне. Границы панели и трёх графиков можно перетаскивать мышью.
Основной сигнал расположен сверху, модель импульса и спектр — под ним.
Графики Generated Signal и Pulse Model используют один виджет: колесо мыши
масштабирует ось времени, перетаскивание перемещает вид, двойной щелчок
восстанавливает полный диапазон. Предпросмотр импульса хранит до 200 тысяч точек;
при большем числе отсчётов он прореживается, шаг указан во всплывающей подсказке.
Это ограничение предпросмотра не влияет на генерацию и экспорт.
Generate и меню Export (CSV/WLF) всегда доступны внизу вкладки;
пункты экспорта включаются после успешной генерации сигнала.

Amplitude Spectrum использует тот же интерактивный виджет, что и оба временных
графика. Спектр обновляется при изменении распределения и его параметров, без
нажатия Generate. Вертикальная ось показывает долю в процентах (сумма долей 100%).
Для Constant рисуется линия 100% на выбранной амплитуде. Файловые веса
нормируются по сумме, одинаковые амплитуды объединяются. Для стандартных
распределений строится гистограмма из 50 000 пробных значений в 64 интервалах;
её генератор случайных чисел независим от генератора сигнала. Это предпросмотр
заданного распределения амплитуд до ADC Clipping, а не измеренный спектр записи.

В группе Generated signal можно включить ADC Clipping (по умолчанию выключен)
и задать симметричный уровень ограничения (по умолчанию ±1 В). Обрезание
применяется к итоговой сумме импульсов и шума. График Generated Signal,
диагностика и экспорт используют один и тот же обрезанный массив;
предпросмотр Pulse Model сохраняет исходную форму.

Справа от Generated Signal находится Output diagnostics. Максимальная амплитуда
вычисляется как максимум отсчётов итогового массива. Detected pulses — число
обнаруженных положительных пиков, также рассчитанное только по массиву,
без использования списка событий или параметров модели. Порог детектора равен
максимуму из 1% размаха записи и шести оценок sigma шума. Sigma оценивается
по медиане абсолютных разностей соседних отсчётов (до 100 тысяч пар).
Для регистрации следующего пика необходим спад и новый подъём на этот порог;
плоская обрезанная вершина считается одним пиком. Порог отображается в панели.
Слитые импульсы нельзя однозначно разделить по готовому сигналу; слабые импульсы
могут быть пропущены, а шум может дать ложные пики. Поэтому это независимая
измеренная оценка числа импульсов, а не точный счётчик исходных событий.

## Форматы `data/`

Исходный импульс рассчитывается по модели. Загрузка файлового шаблона удалена из генератора; `data/pulse_templates/` содержит архивные данные и при генерации не используется.

Спектр амплитуд — две колонки: `амплитуда_В  вес`. Пример: `amplitude_spectrum_example.txt`. Кнопка **Load Amplitude Spectrum**, режим амплитуд: *From file*. Значения читаются непосредственно в вольтах; для старых файлов в кодах FPGA необходим предварительный пересчёт по известной калибровке.

CSV сигнала (вкладка усилителя): `time,amplitude` или одна колонка амплитуд.
Генератор экспортирует CSV с заголовком `time_s,amplitude_V`. Числа амплитуды
в CSV и файле данных WLF выражены в вольтах без дополнительного масштабирования.

## Модель импульса (спецификация v1.0)

Для x = t − t0 ≥ 0:

```text
F(x) = exp(-x/tau_f) - exp(-x/tau_r)
       - beta * (exp(-x/100 ns) - exp(-x/tau_r))
y(t) = A * F(x) / Fmax
Fmax = max F(x), x >= 0
```

До t0 сигнал равен нулю. Значения по умолчанию: A = 1 В, tau_r = 6 нс,
tau_f = 20 нс, beta = 0.08. tau_u = 100 нс и базовая линия 0 фиксированы.
Параметры задаются в Signal Generator; предпросмотр обновляется сразу.
Амплитуда A, среднее и sigma нормального распределения, а также Noise stddev
задаются в вольтах. Lambda экспоненциального распределения измеряется в 1/В;
mu и sigma логнормального распределения относятся к ln(A / 1 В) и безразмерны.
Значение 1 В выбрано как новое начальное значение; оно не является пересчётом
12 000 кодов FPGA из спецификации, поскольку калибровка в проекте не задана.
При beta = 0 отрицательная составляющая отключается. beta не равна отношению
амплитуд отрицательного и положительного пиков, а tau_r/tau_f не равны
измеренным временам фронта и FWHM.

Fmax вычисляется на внутренней логарифмической сетке с последующим численным
уточнением максимума, независимо от выходной частоты дискретизации.
A меняет только высоту: нормированная форма и FWHM изолированного импульса
не зависят от A. Дискретный максимум может быть ниже A, если сетка не попала
в непрерывный пик. При наложении импульсов и добавлении шума наблюдаемая ширина
суммарного сигнала может отличаться от ширины одиночного импульса.

По умолчанию выбран Constant A. В остальных режимах распределение задаёт
непосредственно A каждого события в тех же единицах амплитуды; поле A используется
только для предпросмотра. Спектр из файла содержит амплитуды и веса, а не форму
сигнала. Отрицательные или нечисловые амплитуды вызывают сообщение об ошибке
(включая отрицательные реализации нормального распределения).

Времена событий сохраняются без округления: каждый отсчёт вычисляется при
x = k/fs − t0. Pre-trigger (по умолчанию 100 нс) задаёт начальный участок
базовой линии. В конце заданной Duration резервируется интервал затухания хвоста
до уровня менее 1e-12 от A. События генерируются только между этими интервалами;
слишком короткая Duration вызывает сообщение об ошибке. Хвост за этим пределом
опускается с той же погрешностью. Noise stddev добавляет отдельный гауссов шум
после суммирования импульсов; 0 отключает шум. Нулевая частота событий формирует
только базовую линию и выбранный шум.

Ограничения интерфейса: до 800 миллионов отсчётов и до миллиона ожидаемых событий
на одну генерацию. При изменении настроек после генерации WLF сохраняет частоту
и длину уже сформированного сигнала.

При частоте 800 МГц максимальная длительность составляет 1 секунду.
Предел задан в `SignalSynthesisService::maxSamples`; интерфейс и ядро используют
общую проверку `sampleCount()`. Один секундный массив `double` занимает 6,4 ГБ
памяти (без учёта прочих данных приложения). График и экспорт используют один
общий неизменяемый массив. При повторной генерации старый сигнал сохраняется до
получения нового, поэтому пиковое потребление памяти может быть существенно выше.
Генерация и экспорт пока выполняются синхронно: длинная запись может занять
значительное время, а текстовый файл — значительно больше места, чем массив.

## Проверки модели без Qt

Нужны CMake и компилятор C++17; при необходимости укажите генератор и компилятор:

```bash
cmake -S . -B build/core-tests -DBUILD_CORE_TESTS_ONLY=ON
cmake --build build/core-tests
ctest --test-dir build/core-tests --output-on-failure
```

Проверяются нормировка пика, независимость FWHM от A, beta = 0, отрицательный
хвост, разные частоты дискретизации, дробные времена событий, наложение,
амплитуды распределения, шум, базовая линия и отклонение некорректных параметров.
